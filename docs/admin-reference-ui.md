# Admin reference screens

The existing Angular app now uses the supplied layouts for Returns Management,
Add Product, Product Detail, Product Promotions, Create Promotion, and Promotion Detail.

## Routes

- `/admin/returns`: return statistics, customer/product enrichment, status and date filters, selection, CSV export, pagination and the existing new-return flow.
- `/admin/products/add`: category/brand selection, product images, publishing, dynamic variant generation, removable attribute values and bulk updates.
- `/admin/products/view/:id`: gallery, product information, variants, inventory, attributes, images, activity and links to orders/promotions.
- `/admin/promotions`: list filters and the inline four-tab creation flow.
- `/admin/promotions/add`: five numbered sections with product selection, discount preview and summary.
- `/admin/promotions/:id`: details, assigned product prices/stock, conditions, status timeline and supported lifecycle actions.

## Backend integration

Returns use the backend's named filter fields, not `criteria_type`/`criteria_value`.
New returns resolve catalog product IDs from the selected order SKU and validate
the requested amount against the order line total. Related customer, order,
payment, inventory and product data use their existing endpoints.

Promotions save the existing request contract. Percentage/fixed discounts,
minimum purchase, maximum discount, usage limits, scheduling, activation,
disabling, archiving and SKU assignments are supported. The selected SKUs are
assigned after saving; a failed assignment retains the saved promotion ID so a
retry updates the draft rather than creating another record. Duplicate loads all
assignment pages. A saved promotion remains a draft until explicitly activated
or scheduled.

Catalog SKU codes are generated by the server. Product duplication copies the
editable fields and clears IDs/barcodes; new images must be uploaded before saving.
Missing catalog image URLs show a neutral product placeholder.

## Fields requiring backend work

Product short description, cost price, units, featured flag, SEO, tags, weight
and dimensions are shown as unavailable. Sale prices come from promotions.
Buy-X-get-Y, bundles, category/brand targeting, customer-group exclusions,
minimum quantities, banners, product reviews and promotion analytics have no
supporting contracts. Their controls are disabled or the corresponding tab
explains the limitation; they do not submit fake values.

Approved/rejected return cards and promotion status cards are labelled as counts
on the current page because the existing summary endpoints do not supply those
global counts. Promotion search, type and date filters apply to the current page.
Payment-method return filtering applies to the enriched current page.

Validation includes production compilation, automated request/workflow tests,
and browser checks against the existing local test data. No real payment or
refund provider transaction is executed by these checks.

### Inventory, customer and group continuation — October 9, 2026

- Inventory now has the reference-style list, filters, detail panel and stock movement tabs.
- Stock In, Stock Out and Adjustments have Basic Information, Select Products,
  Review and Complete steps. Quantities are validated against reserved stock.
  Retry within the current page skips stock lines whose updates succeeded.
- Stock In uses restock; Stock Out and Adjustments use the existing exact-quantity
  endpoint. The client rereads quantities before saving, but the server does not
  provide atomic compare-and-set or a transaction for an entire multi-item document.
- Reference, date, reason and notes in stock flows are review/print information;
  the inventory API does not persist stock documents, suppliers, costs or attachments.
- Warehouses summarizes existing inventory locations. Warehouse profile creation,
  addresses and managers require a warehouse API and remain unavailable.
- Customers uses the existing account list with a detail sidebar. The create form
  sends supported account fields and a manually supplied existing customer role ID.
  No role-list endpoint is available. Profile images, preferences and address
  creation for another account are not supported here.
- Access Groups at `/admin/groups` lists permission groups and creates groups with
  selected real function permissions. It is separate from customer groups.
  Membership management remains unavailable; existing access-record management
  remains accessible under Users.
- Source and templates are formatted across readable lines.
- Production build passed. Automated tests: 61 passing in 13 files, including
  reserved-stock validation, stale review detection and partial-failure retry.
- Live browser verification on October 9 was blocked at sign-in by
  “Cannot reach the shop.” No live stock or permission changes were made.

### AI Assistant reference — October 9, 2026

  cards, chat composer, quick actions, tools, knowledge sources and conversation list.
- Uses `/api/ai/admin/chat` for administrators and `/api/ai/chat` for other accounts.

  the screen reports those limits rather than claiming an active connection.
